# Site and calculator review — 2026-11-11

Review of the website, the data/pricing pipeline and the cluster jewel crafting
calculator, done while waiting for the league after Allflame. Findings come from
four parallel reviews (mechanics, solver math, calculator UI, site/pipeline) with
probes; items marked *inferred* were read from code and not reproduced.

Status key: `[ ]` open, `[x]` fixed, `[~]` partly fixed (see note).

## F. Found from a real test (Flow of Life + Wicked Pall, medium Chaos DoT) — batch 2

Export: 563c, plan with zero steps, Harvest "not searched". Replaying the exported
request showed the answer depended on machine speed: 564c, 1,347c (fracture route)
or no route at all at a 10s budget.

- [x] **F1. Every junk mod was its own search state.** `rules/actionDiscovery.ts`
  (`getCanonicalStateKey`), `domain/ModPool.ts`, `domain/Mod.ts` (`ExclusionClass`),
  `domain/TargetDefinition.ts` (`getInterchangeableJunkSignature`),
  `rules/actionRegistry.ts` (Harvest aggregation key). The graph enumerated every
  junk-suffix pair, so 5,000 states covered a fraction of the craft and the result
  was whatever the truncated graph happened to contain. **Done:** non-target mods
  whose exclusion groups hold the same (side, notable, ilvl, weight) members now
  share a state. Mods that are fractured, match a requirement, or share a group
  with a target keep their identity. Exactness is pinned by
  `test/unit/junkEquivalence.test.ts` (identical cost, 99 vs 2,094 states); a
  larger manual check gave 79.0737c both ways with 123 vs 6,189 states, 0.2s vs
  31s. The user's request now closes at 936 states.
- [x] **F2. "Never finishes" was decided by rounding.** `genericSearch.ts`
  (`computePolicyTrust`). Absorption came out 0.99999998 against a 1 - 1e-8
  threshold on slow reroll loops, flipping 133 states between RESOLVED and
  IMPROPER every pass until the round timed out. **Done:** a state absorbs with
  probability 1 iff it cannot reach a state with no path to a terminal; that is
  now decided on the graph, not from the numeric solve.
- [x] **F3. Policy repair re-adopted actions it had just rejected.** Same loop;
  **Done:** an action abandoned as improper stays abandoned for that resolution.
- [x] **F4. Value iteration hit its 1,000-sweep cap far from converged**
  (411c estimate vs 866c true on the Primordial Bond fixture), and the greedy
  policy from it was improper, so the exact solve was singular. **Done:** when
  that happens a proper seed policy is built (safe actions only, each state steps
  toward a terminal) and exact policy iteration runs from it.
- [x] **F5. Acquisition-menu routes under-counted bases.** `optimizerService.ts`
  (`createResolvedPolicyBundle`). Re-buying a base after a failed fracture was

- [x] **F6. Plan rules could not say "no notable slots left".** `craftPlan.ts`

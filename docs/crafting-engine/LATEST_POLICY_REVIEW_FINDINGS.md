# Latest Crafting Policy Review Findings

## Scope

This document reviews the latest `output.txt` generated by:

```text
node crafting-engine/scripts/optimizeCraftDemo.ts > output.txt
```

The latest implementation introduces a Markov/Bellman-style state-aware policy comparison and removes the +8-only Intelligence finishing requirement.

The main conclusions from this run are:

- the T1 Intelligence target is now correctly treated as **any T1 roll in the +6 to +8 range**;
- the optimizer now explicitly compares multiple Harvest stopping strategies instead of assuming that the first T1 ES hit always ends Harvesting;
- the state-aware policy currently prefers stopping on T1 ES and finishing 35% Effect with Allflame Exalts rather than deliberately fishing Harvest for T1 ES + 35% Effect;
- the policy cost model is internally consistent with Monte Carlo, but some mechanics and acquisition models remain approximate;
- reporting still needs clearer attribution of recovery-loop costs before it should be considered final user-facing output.

Do **not** add unit tests for this work unless explicitly requested. Continue validating through diagnostic scripts, reference-craft runs, analytical calculations, Monte Carlo cross-comparison, and focused regression scripts.

# Finding 3 — Keep the State-Aware Harvest Decision Permanently

Even though Strategy C currently matches Strategy A, the state-aware decision should remain part of the solver.

Representative current state:

```text
Fractured T1 Int
T1 ES
```

Current continuation values:

```text
Allflame Exalt 35% Effect:   ~1265.7c
Harvest Reforge Defence:     ~1323.4c
```

Difference:

```text
~57.7c
```

This is not a huge gap.

Changes in any of the following could flip the optimal choice:

```text
Lifeforce price
Exalted Orb price
Allflame mechanics
mod weights
sale values
Harvest generation rules
available recovery actions
```

Therefore never replace the state-aware comparison with a hard-coded rule such as:

```text
if T1 ES exists, always stop Harvesting
```

The correct rule is:

```text
choose the action with the lowest continuation cost / highest continuation value from the actual ItemState
```

```text

GAME-MECHANICS FIDELITY: PARTIAL

```

The first two statements are reasonable.

The third should be changed.

"Global optimality" cannot be proven merely by being optimal among the policies/actions currently included in the search space.

```text

PROVEN

GLOBAL OPTIMALITY:
NOT YET PROVEN
```

Global optimality should only be claimed once the relevant legal crafting action set is sufficiently complete and the search can actually compare all meaningful routes.

# Finding 8 — Stepwise Cost Attribution Still Needs Improvement

The total analytical and Monte Carlo expected cost can agree even while individual reported step costs differ substantially.

The current conceptual issue is that analytical steps show the cost of progressing from a clean local state, while Monte Carlo step buckets include repeated recovery loops triggered by failures in later stages.

For example:

```text
Initial T1 ES acquisition:
  Expected Harvests: 14

Full craft:
  Expected Harvest actions across all rebuilds: ~398
```

Both numbers can be valid, but they answer different questions.

The report should distinguish them explicitly.

### Recommended Step 2 presentation

```text
STEP 2 — Establish / Re-establish T1 ES

Initial acquisition:
  Chance per Harvest:          7.1429%
  Expected Harvests:          14.00
  Initial acquisition cost:   21.9c

Recovery contribution:
  Expected additional Harvests caused by later failures: XXX.XX
  Expected rebuild Harvest cost: XXX.Xc

Full-craft Harvest usage:
  Expected total Harvests:    ~398
  Expected total Harvest cost: XXX.Xc
```

Apply the same concept to:

```text
Annulments
Exalted Orbs
Harvests
other recovery actions
```

This will make the user-facing plan much easier to understand.

